# Telegram: ролики в канал автоматически

Каждый готовый Shorts может уходить ещё и в ваш канал Telegram: видео, подпись и обложка. Работает
через **официальный Bot API** Telegram. Это бесплатно, без сторонних сервисов, пароль и номер
телефона никому не передаются. Настройка — 10 минут, один раз.

Включается только явно: без ключей `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` ничего не отправляется.

## Что нужно знать заранее

- Публикует **бот** — ваш собственный, его создают за минуту у [@BotFather](https://t.me/BotFather).
  В канале бот должен быть **администратором** с правом «Публикация сообщений». Посты выходят от
  имени канала, как ваши собственные.
- **Отложенной публикации у ботов нет.** Выпускать «в 12:00 и 19:00» умеет наш workflow в GitHub:
  дважды в день он отправляет следующий ролик из очереди.
- **Лимит бота — 50 МБ на файл.** Наши ролики по умолчанию собираются в высоком качестве
  (≈ 11 Мбит/с): шорт на 35 с весит ≈ 50 МБ, на минуту — ≈ 80 МБ. Такой файл программа сама
  пережимает в копию ≈ 45 МБ (≈ 6 Мбит/с для минутного ролика — на экране телефона разницы не
  видно). Это ffmpeg из Remotion, ставить ничего не нужно; занимает 1–2 минуты. Исходный
  `video.mp4` не меняется.
- **Подпись** — до 1024 символов (лимит Telegram). Берётся `telegram.txt`, если вы его написали,
  иначе `instagram.txt`. Длинная подпись сокращается по абзацам: хук, призыв и хэштеги остаются.
- **Обложка** — `cover.jpg` (тот же кадр, что у Reels). Если её нет, Telegram покажет первый кадр.

## Шаг 1. Бот

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) → **«Запустить»** (Start).
2. Отправьте `/newbot`.
3. Имя бота — любое, например `Суть за минуту — публикация`.
4. Адрес (username) — латиницей и обязательно с `bot` на конце, например `sut_za_minutu_post_bot`.
5. BotFather пришлёт **токен** — строку вида `123456789:AAH…`. Это `TELEGRAM_BOT_TOKEN`.

> Токен — полный доступ к боту. Никому его не пересылайте и не публикуйте. Если он утёк:
> @BotFather → `/mybots` → бот → **«API Token» → «Revoke current token»**, затем замените токен в
> `.env` и в секретах GitHub.

## Шаг 2. Бот — администратор канала

Канала ещё нет? Telegram → **«Новый канал»**, название — как у YouTube-канала (`channel.json`).

В приложении на телефоне:

1. Откройте канал → нажмите на его название вверху.
2. **«Изменить»** (карандаш) → **«Администраторы»** → **«Добавить администратора»**.
   На Android: **⋮ → «Управление каналом» → «Администраторы» → «Добавить администратора»**.
3. Найдите бота по адресу из шага 1 (`@sut_za_minutu_post_bot`) и выберите его.
4. Оставьте включённым право **«Публикация сообщений»**. Остальные права боту не нужны — их можно
   выключить.
5. **«Готово»** / **«Сохранить»**.

На компьютере (Telegram Desktop): канал → **⋮ → «Управление каналом» → «Администраторы» →
«Добавить администратора»**.

## Шаг 3. Id канала (TELEGRAM_CHAT_ID)

**Публичный канал** (есть адрес `t.me/имя`): можно просто вписать `@имя`, например `@sutzaminutu`.

**Закрытый канал** — нужен числовой id, он начинается с `-100`. Проще всего так:

1. Сразу после шага 2 впишите в `.env` в папке `video-studio` только токен:
   ```
   TELEGRAM_BOT_TOKEN=123456789:AAH…
   ```
2. Выполните:
   ```bash
   npm run telegram-check
   ```
   Программа покажет каналы, куда бота добавили за последние сутки, и их id:
   ```
   ✔ бот: @sut_za_minutu_post_bot (Суть за минуту — публикация)
   TELEGRAM_CHAT_ID не задан. Бот видел эти каналы и группы (события за последние сутки):
     -1001234567890  канал  «Суть за минуту»
   ```
   Канала нет в списке (бота добавили больше суток назад)? Опубликуйте в канале любое сообщение
   (потом его можно удалить) и запустите команду снова.

Другие способы:

- **Ссылка на пост.** В канале нажмите на любой пост → **«Копировать ссылку»**. Получится
  `https://t.me/c/1234567890/15`. Её можно вписать в `TELEGRAM_CHAT_ID` как есть, или вписать
  `-100` и число после `/c/`: `-1001234567890`.
- **Веб-версия.** Откройте канал на [web.telegram.org/a](https://web.telegram.org/a/): в адресной
  строке после `#` будет id вида `-1001234567890`. (В версии `/k/` там `-1234567890` — тогда
  допишите `100` после минуса.)

## Шаг 4. Проверка и пробная отправка

Впишите в `.env` оба значения:

```
TELEGRAM_BOT_TOKEN=123456789:AAH…
TELEGRAM_CHAT_ID=-1001234567890
```

и выполните `npm run telegram-check`. Должно быть три галочки:

```
✔ бот: @sut_za_minutu_post_bot (…)
✔ канал: «Суть за минуту», id -1001234567890
✔ права: администратор, может публиковать
```

Пробная отправка готового ролика:

```bash
npm run upload -- out/<папка ролика> --to telegram
```

## Шаг 5. Секреты GitHub

**Репозиторий на github.com → Settings → Secrets and variables → Actions → New repository secret:**

| Секрет | Что вписать |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен из шага 1 (`123456789:AAH…`) |
| `TELEGRAM_CHAT_ID` | id из шага 3 (`-1001234567890` или `@имя`) |

Необязательная **Variable** (вкладка рядом): `TELEGRAM_QUEUE_SINCE` — с какого ролика начать.
Код темы, например `14a`: в очередь попадут 14a, 14b, 15a… (раньше по плану — нет). Или дата вида
`2026-10-12`: релизы, опубликованные раньше, не попадут. Поставьте её, если не хотите, чтобы в
канал по одному ушли все уже выпущенные ролики (у нас это 01a–13b).

## Как отправляются ролики

### Сразу, с компьютера

```bash
npm run upload -- out/<папка ролика> --to telegram
npm run upload -- out/<папка ролика> --to youtube,telegram --schedule    # YouTube в слот, Telegram сразу
npm run make -- --script scripts/x.json --upload youtube,telegram --schedule
```

После отправки в папке ролика появляется `telegram-result.json` со ссылкой на пост. Второй раз
тот же ролик не уйдёт: будет сообщение «уже отправлен» (`make` при пересборке того же сценария
просто пропустит этот шаг). Нужно ещё раз — `npm run upload -- out/<папка ролика> --to telegram --force`.

Своя подпись для канала: положите рядом с роликом `telegram.txt` — уйдёт она, а не `instagram.txt`.

### По расписанию, через GitHub (12:12 и 19:12 по Москве)

1. **Очередь** — ролики по плану: релизы GitHub с файлом `08a-….mp4`, по порядку кодов
   (01a, 01b, 02a…). Их создаёт **«video-studio: ролик»** с `upload = release` (и пакет
   `mode = batch`).
   - Ролик пересобрали и появился второй релиз с тем же кодом — уйдёт **только свежий**, один раз.
   - Код, у которого хоть в одном релизе есть `telegram-published.json`, больше не отправляется.
   - Ролики на других языках (`en-08a-….mp4`) и без кода (`video.mp4`: демо, ролик по теме) в
     очередь не попадают — такой можно отправить вручную, указав его тег (ниже).
2. Workflow **«video-studio: Telegram по расписанию»** при каждом запуске отправляет **первый**
   ролик очереди и добавляет в его релиз файл `telegram-published.json`.
   - Запустить вручную: **Actions → «video-studio: Telegram по расписанию» → Run workflow**.
     Флажок `dry_run` только покажет, что будет отправлено.
   - **Включить расписание**: в файле `.github/workflows/video-studio-telegram.yml` уберите `#`
     перед строками `schedule:` и двумя `- cron:` и сохраните (Commit changes). После этого он
     запускается в 12:12 и 19:12 по Москве — через несколько минут после выхода ролика на YouTube.
     Если GitHub перегружен, запуск может задержаться на 5–20 минут. Расписание работает, только
     когда файл лежит в ветке по умолчанию (`main`).
3. Очередь кончилась — workflow просто напишет «Очередь Telegram пуста».

- **Отправить вне очереди**: при ручном запуске укажите тег релиза в поле `tag`.
- **Убрать ролик из очереди**: добавьте в его релиз любой файл с именем `telegram-published.json`
  (**Releases → релиз → Edit → перетащите файл → Update release**).
- **Отправить ещё раз**: удалите из релиза файл `telegram-published.json` (если у ролика несколько
  релизов — из всех) или запустите вручную с тегом нужного релиза.

### Защита от дублей

Найти свои прошлые посты в канале бот не может (истории канала в Bot API нет), поэтому программа
не повторяет отправку вслепую:

- Отметка ставится **прямо перед** отправкой. Если связь оборвалась посреди загрузки (или
  Telegram ответил ошибкой сервера), непонятно, вышел ли пост. Тогда ролик **помечается как
  отправленный**, а в сводке запуска появляется предупреждение «неизвестно, вышел ли пост».
  Проверьте канал: если поста нет — удалите `telegram-published.json` из релиза (с компьютера —
  повторите с `--force`).
- Если Telegram сам ответил «подождите» (лимит запросов), программа ждёт указанное время и
  повторяет — это безопасно.

## Если что-то не так

| Сообщение | Что делать |
|---|---|
| `Не заданы TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID` | Шаги 1 и 3; в GitHub — шаг 5 |
| `токен TELEGRAM_BOT_TOKEN не принят` | Токен перевыпущен или бот удалён: @BotFather → `/mybots` → бот → «API Token». Обновите `.env` и секрет |
| `TELEGRAM_BOT_TOKEN не похож на токен бота` | Скопирован не весь токен. Нужна строка `число:буквы` целиком |
| `канал TELEGRAM_CHAT_ID не найден` | Id закрытого канала начинается с `-100`; бот должен быть в канале. `npm run telegram-check` покажет верный id |
| `ссылка-приглашение не подходит` | Ссылка `t.me/+…` — это приглашение, а не id. Шаг 3 |
| `бот не состоит в канале` / `нет права публиковать` | Шаг 2: бот — администратор с правом «Публикация сообщений» |
| `Видео … больше 50 МБ … пережать не вышло` | Соберите ролик с `VIDEO_QUALITY=standard` (файл будет меньше) или отправьте в канал вручную |
| `неизвестно, вышел ли пост` | Проверьте канал. Поста нет — повторите: с компьютера с `--force`, в GitHub удалите `telegram-published.json` из релиза |
| `Telegram просит подождать` | Лимит запросов Telegram. Повторите позже |
| `telegram-check` не видит канал | Бота добавили больше суток назад: опубликуйте в канале любое сообщение и запустите снова. Или возьмите id из ссылки на пост (шаг 3) |
| `У бота включён webhook` | Бот подключён к другому сервису. Создайте для публикации отдельного бота (шаг 1) |
| Workflow: «Очередь Telegram пуста» | Нет релизов с роликом `08a-….mp4`, который ещё не отправлен (или все раньше `TELEGRAM_QUEUE_SINCE`). Соберите ролики с `upload = release` |
| Запуск снова и снова падает на одном ролике | Ошибка не про связь (например, ролик не пережимается). Уберите его из очереди: добавьте в релиз файл `telegram-published.json` |
