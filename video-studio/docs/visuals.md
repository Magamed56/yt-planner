# Кадры по теме: откуда берутся фото и видео в роликах

Коротко для владельца канала:

1. **Заведите два бесплатных ключа — Pexels и Pixabay — и добавьте их в секреты GitHub.** С ними в
   роликах будут живые стоковые видео. Без ключей конвейер берёт только реальные фото из Wikimedia
   Commons и Openverse, а этого для большинства тем мало.
2. **Без ключей ролики тоже собираются.** Картинку не по теме конвейер теперь не ставит: такая
   сцена остаётся на чистой моушен-графике (текст, иконки, анимация).

## Что было не так (ролики 10a–12b)

В логах сборки 10a–12b (GitHub Actions, 09.10.2026) написано «Pexels пропущен: не задан
PEXELS_API_KEY» и то же про Pixabay. Поэтому все кадры шли из Wikimedia Commons. Commons ищет по
словам, а не по смыслу, и конвейер брал первый файл, где совпало хотя бы одно слово запроса:

| Запрос сцены | Что попало в ролик |
|---|---|
| `old book candle desk` (10b) | гравюра письменного стола 1720 года |
| `person covering one eye` (10b) | улица в Таиланде со статуями поваров |
| `cat tongue close up` (10a) | «Tongue of the forest» — лес, а не кошачий язык |
| `old circuit board closeup` (11a) | гоночная трасса («racing circuit») |
| `hands weaving copper wire` (11a) | руки, плетущие пальмовые листья |
| `old university stone building` (12b) | университет Финдли (США), а не Оксфорд |
| `lake city aerial mountains` (12b) | горы Ньюфаундленда, а не Теночтитлан |

Причины:
- **Мягкая проверка.** Хватало одного слова из запроса в названии файла.
- **Вторым запросом шли первые два слова.** Так появлялись «old book», «city street».
- **Не отсекались не-фото:** гравюры, картины, муралы.
- **Сценарий запрещал имена в запросе.** Вместо «Tenochtitlan» LLM писал «lake city aerial
  mountains», и Commons не мог найти настоящий объект.

## Как подбирается кадр теперь

Источники пробуются по порядку `VISUALS`. По умолчанию это `pexels,pixabay,wikimedia,openverse,cloudflare`.
Источник без ключа тихо пропускается. Сначала берутся видео всех стоков, потом фото. В рубриках
история, природа и космос реальные фото идут первыми (`VISUALS_REAL_PILLARS`).

Каждый найденный файл проходит проверку «по теме» (`src/pipeline/visuals/relevance.ts`):

- **Главные слова запроса** — конкретные существительные. Стиль и ракурс («cinematic», «close up»,
  «dark») не считаются. Признаки («old», «blue») весят мало.
- **Предмет ролика.** Если слово повторяется в запросах многих сцен (`cat` в 4 сценах из 7), без
  него файл почти наверняка не по теме, и оно весит вдвое.
- **Где нашлось слово.** Больше всего весит название файла, меньше — категории, ещё меньше —
  описание. Нужны главные слова в названии или категориях и хотя бы половина веса всего запроса.
  Исключение: короткое название почти целиком из слов запроса («Red Sunset» на «red sunset
  horizon city»).
- **Составные понятия не разрываются.** На «sea lion» файл просто про льва не подходит.
- **Только фото.** Гравюры, рисунки, картины, муралы, карты, схемы, логотипы, гербы, флаги,
  сканы страниц и 3D-рендеры отсекаются по названию, категориям Commons и описанию. Исключение —
  запрос сам их просит: «Edme Mariotte portrait», «old map of Oxford».
- **Размер и формат.** Для Commons — JPEG, PNG или WebP, короткая сторона не меньше 1080 px
  (`VISUALS_MIN_PHOTO_PX`), без панорам.
- **Запрос к Commons — только предмет кадра.** Например, `book candle desk` вместо
  `old book candle desk`, `cat tongue` вместо `cat tongue close up`. Commons требует все слова
  запроса, и лишние только мешают. Имя из `imagePrompt` прямо перед предметом добавляется:
  «Saturn V style rocket» → `saturn rocket launch`, то есть настоящие запуски «Аполлона».
- **Стоки (Pexels, Pixabay) проверяются мягче.** Они ищут по смыслу, но описание у них короткое:
  адрес страницы, alt, теги. Отсекается только явный промах, например «woman doing yoga» на
  «cat tongue». Если в запросе есть имя собственное (`Tenochtitlan model`), клип со стока берётся,
  только когда это имя есть в его описании. Иначе ход переходит к реальным фото.

Если ни один файл не прошёл проверку, сцена остаётся на моушен-графике. В логе шага «Визуал» теперь
видно название каждого взятого файла: `s4: картинка — Wikimedia Commons: … — «Old book and burning
candle on a wooden desk»`. Если на Commons по теме ничего нет, в логе так и написано.

Проверка правил — `npx tsx src/dev/visuals-test.ts`, без сети. Тест прогоняет все 39 настоящих
подборов 10a–12b из логов CI: 18 случайных совпадений отсекаются, 21 удачный кадр остаётся.

### Новые сценарии

Подсказка для LLM (`src/pipeline/script/prompt.ts`, поле `visualQuery`) теперь просит начинать
запрос с настоящего названия, если сцена про реальный объект или место: «Apollo Guidance Computer»,
«Tenochtitlan model», «Radcliffe Camera Oxford». Исторического человека просит писать как
«Edme Mariotte portrait». Стиль и свет в запрос не пишутся. Старые сценарии можно поправить руками:
`visualQuery` в `scripts/sut-….json`.

## Что сделать владельцу

### 1. Pexels — живые видео (главное)

1. Зарегистрируйтесь на [pexels.com](https://www.pexels.com/join/) и откройте
   [pexels.com/api](https://www.pexels.com/api/) → **Your API Key**. Это бесплатно; лимит —
   200 запросов в час, на ролик уходит до 20–25.
2. На GitHub: репозиторий → **Settings → Secrets and variables → Actions → Secrets →
   New repository secret**. Имя `PEXELS_API_KEY`, значение — ключ.

### 2. Pixabay — ещё видео

1. Войдите на [pixabay.com](https://pixabay.com/accounts/register/) и откройте
   [pixabay.com/api/docs](https://pixabay.com/api/docs/). Ключ показан в разделе «Parameters»,
   строка `key`.
2. Создайте секрет `PIXABAY_API_KEY` так же, как для Pexels.

### 3. Проверить

- **Actions → «video-studio: проверка ключей» → Run workflow.** В сводке должно быть
  `PEXELS_API_KEY — есть` и `PIXABAY_API_KEY — есть`.
- В логе следующей сборки, в шаге «Визуал», не должно быть строк «Pexels пропущен». В описании
  ролика в блоке «Видео и фото» появятся строки Pexels и Pixabay.

Локально — те же ключи в `video-studio/.env` (образец — `.env.example`).

Атрибуция: Pexels и Pixabay её не требуют. Конвейер всё равно пишет автора и ссылку в описание, как
и для Wikimedia (там это обязательно для CC BY и CC BY-SA).

### Что будет без ключей

- Кадры только из Wikimedia Commons и Openverse, и только те, что прошли проверку «по теме».
- Для бытовых сцен (рука с телефоном, мокрые пальцы) настоящих фото по теме мало, поэтому часть
  сцен будет на моушен-графике. Это ожидаемо и лучше случайной картинки.
- Если на ролик пришлось 0–2 кадра, конвейер сам ключей не добавит — только владелец, по шагам выше.

## Судья Claude (по желанию, платно)

Правила видят только английские слова. Судья Claude читает и русский текст сцены. Например, он
отличает «Old manuscripts of Indonesia» от рукописи для ролика про Оксфорд.

- **Как включить:** GitHub → Settings → Secrets and variables → Actions → **Variables**:
  `VISUALS_JUDGE` = `claude`. Нужен секрет `ANTHROPIC_API_KEY` — тот же, что для сценариев на Claude.
  Локально — те же имена в `.env`.
- **Что делает:** получает до 6 файлов, прошедших правила (название, описание, категории, без
  картинок) и отвечает номером лучшего или «ни один не подходит».
- **Цена:** модель по умолчанию — `claude-haiku-4-5`, самая дешёвая из уже используемых в проекте:
  $1 за миллион входных токенов и $5 за миллион выходных. Один вызов — около 1–1,5 тыс. токенов,
  ≈ $0.0015. На Shorts из 7–8 сцен уходит 8–15 вызовов, это ≈ $0.01–0.02 за ролик. Итог печатается в
  логе шага «Визуал»: «судья Claude (…): N запросов, ≈ $…». Другая модель — `VISUALS_JUDGE_MODEL`;
  например, `claude-haiku-5-5` ещё дешевле.
- **Если ключ неверный, кончились деньги или нет связи,** подбор продолжается по бесплатным правилам.
  Ролик не падает.

## Настройки

| Переменная | Что делает | По умолчанию |
|---|---|---|
| `VISUALS` | порядок источников; `none` — без кадров | `pexels,pixabay,wikimedia,openverse,cloudflare` |
| `PEXELS_API_KEY`, `PIXABAY_API_KEY` | стоковые видео и фото | — |
| `VISUALS_MIN_PHOTO_PX` | минимальная короткая сторона фото Commons, px | 1080 |
| `VISUALS_REAL_PILLARS` | рубрики, где реальные фото идут первыми | `history,nature,space` |
| `WIKIMEDIA_LICENSES` | разрешённые лицензии: `pd,cc0,cc-by,cc-by-sa` | все четыре |
| `VISUALS_JUDGE`, `VISUALS_JUDGE_MODEL` | судья Claude (платно) | выключен, `claude-haiku-4-5` |

После смены правил подбора (`PICK_RULES_VERSION` в `manifest.ts`) кадры прошлых запусков в той же
папке подбираются заново один раз. Дальше они снова берутся из `public/visuals/manifest.json`, и
квоты не тратятся. Подобрать заново вручную — удалить `out/<ролик>/public/visuals`.

## Ограничения

- Правила работают по словам, а не по смыслу картинки. Редкие промахи возможны: файл с точным
  названием, но странным кадром. Судья Claude их уменьшает, но картинки он тоже не видит.
- Видео с Commons (WebM/OGV) не берутся. Почти все они горизонтальные и небольшого разрешения, а
  видео в Shorts кадрируется по центру: от горизонтального кадра остаётся треть. Живые видео —
  с Pexels и Pixabay.
- Русский текст сцены правила не понимают. Конкретику дают английские `visualQuery` и `imagePrompt`
  из сценария, поэтому точный запрос с настоящим названием важнее всего.
