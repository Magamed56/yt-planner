# YouTube: настройка канала «Суть за минуту» и публикация по расписанию

Эта инструкция для тех, кто не программирует. Всё делается мышкой в браузере на компьютере, на
сайте [studio.youtube.com](https://studio.youtube.com). С телефона многие пункты недоступны.

Что понадобится:

- картинки из папки `video-studio/brand/` (их уже нарисовали);
- тексты из файла `video-studio/content/channel-texts.md` (их остаётся только скопировать).

Порядок такой: оформить канал (шаги 1–4), один раз задать настройки загрузки по умолчанию
(шаг 5), подключить автоматическую загрузку (шаг 6). После этого ролики будут выходить сами
в **12:00 и 19:00 по Москве**.

---

## 1. Название и адрес канала

**YouTube Studio → слева «Настройка канала» → вкладка «Профиль».**

- **Название:** `Суть за минуту`.
- **Псевдоним** (адрес канала, `youtube.com/@…`): `sutzaminutu`. Если он занят, по очереди
  пробуйте `sut.za.minutu` и `sut_za_minutu`. Если взяли запасной, поменяйте ссылки в
  `video-studio/channel.json` (поле `links.youtube`), иначе в описаниях роликов будет старый адрес.
- Нажмите **«Опубликовать»** справа вверху.

## 2. Аватар, баннер, водяной знак

Там же: **«Настройка канала» → «Профиль»**. В старом интерфейсе картинки лежат на вкладке
**«Брендинг»**.

| Что | Файл | Где |
|---|---|---|
| Фото профиля | `brand/avatar-youtube.png` | «Фото профиля» → **«Изменить»** → выбрать файл → рамку не двигать → **«Готово»** |
| Баннер | `brand/banner-youtube.png` | «Изображение баннера» → **«Изменить»** → в окне кадрирования ничего не трогать → **«Готово»** |
| Водяной знак | `brand/watermark-youtube.png` | «Водяной знак» → **«Загрузить»** → «Время показа»: **«Всё видео»** |

В конце нажмите **«Опубликовать»**. Новые картинки появляются через несколько минут, иногда до суток.
Подробнее о файлах и как их перерисовать: `brand/README.md`.

## 3. Описание и ссылки канала

**«Настройка канала» → «Профиль»:**

- **«Описание»**: вставьте блок «Описание» из `content/channel-texts.md`, весь текст внутри рамки.
- **«Ссылки»** → **«Добавить ссылку»**: название `Instagram`, адрес `https://instagram.com/sutzaminutu`.
- **«Опубликовать»**.

## 4. Ключевые слова канала

**YouTube Studio → слева внизу «Настройки» (шестерёнка) → «Канал» → «Основная информация»:**

- **«Страна проживания»**: ваша страна.
- **«Ключевые слова»**: вставьте строку из блока «Ключевые слова» в `content/channel-texts.md`.
  Слова разделены запятыми, YouTube сам превратит их в отдельные метки.
- **«Сохранить»**.

## 5. Настройки загрузки по умолчанию

Они нужны для роликов, которые вы загрузите **руками**. Ролики, которые загружает наша программа,
получают все эти настройки и так (категория «Образование», русский язык, «не для детей», отметка
о синтетическом контенте).

**«Настройки» → «Загрузка видео по умолчанию»:**

1. Вкладка **«Основная информация»**:
   - «Параметры доступа»: **«Ограниченный доступ»** (то есть приватно; опубликуете, когда проверите).
   - «Теги»: `суть за минуту, факты, наука, интересно, познавательно`.
2. Вкладка **«Расширенные настройки»**:
   - «Категория»: **«Образование»**;
   - «Язык видео» и «Язык названия и описания»: **«русский»**;
   - «Изменённый контент» (в некоторых версиях «Изменённый или синтетический контент»): **«Да»**.
     Голос в роликах синтезирован, и правила YouTube требуют это отмечать. Если такого пункта
     нет, его ставят у каждого ролика при загрузке: в разделе «Изменённый контент» ответьте «Да».
   - Комментарии: **«Разрешить все»** или «Задерживать потенциально недопустимые» (комментарии
     продвигают ролик, а в каждом ролике есть вопрос зрителю).
3. **«Сохранить»**.

И ещё: **«Настройки» → «Канал» → «Расширенные настройки» → «Аудитория»: «Нет, этот канал не для детей»**.

## 6. Ключи YouTube для GitHub (один раз)

Нужны три ключа: `YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN`. С ними GitHub сам загружает
ролики и проставляет тексты и расписание тем, что вы загрузили руками. Получить их можно тремя способами.

**Ключ уже есть — из bakery-escape (2 минуты).** Для канала игры вы уже создали в Google Cloud
OAuth-клиент «Приложение для ПК»: файл `client_secret….json` лежит в
`candy-escape\tools\studio\secrets\`. Он подходит и для этого канала, новый проект не нужен.
На компьютере, в PowerShell, в папке `yt-planner\video-studio`:

```powershell
npm ci
npm run youtube-auth -- --client-secret C:\Users\maga\games\candy-escape\tools\studio\secrets --save
npm run youtube-fill
```

Вторая команда откроет браузер: войдите в Google и, если спросят, выберите канал **«Суть за
минуту»** (не канал игры). В конце она напечатает имя канала и запишет ключи в `video-studio\.env`
(файл не попадает в git). Токен канала игры в `candy-escape` она не трогает. Третья команда
проставит тексты и время роликам, которые вы уже загрузили в Studio (раздел ниже). Чтобы
запускать это из GitHub с телефона, добавьте три значения из `.env` в секреты GitHub (см. ниже).

Если приложение в Google Cloud в статусе «Testing», аккаунт канала «Суть за минуту» должен быть
в **Audience → Test users** (обычно это тот же Gmail, что и у канала игры).

**Только в браузере, без программ (около 15 минут).**

1. [console.cloud.google.com](https://console.cloud.google.com) → создайте проект (любое имя) →
   **APIs & Services → Library → «YouTube Data API v3» → Enable**.
2. **Google Auth Platform** (в старом интерфейсе «OAuth consent screen») → **Get started**: имя
   приложения `Суть за минуту`, ваша почта, тип аудитории **External** → **Create**. Затем
   **Audience → Test users → Add users** → ваш Gmail. И там же **Publish app** (статус
   «In production»): в статусе «Testing» ключ перестаёт работать через 7 дней.
3. **Clients → Create client** → тип **«Web application»** → в **Authorized redirect URIs**
   добавьте `https://developers.google.com/oauthplayground` → **Create**. Скопируйте
   **Client ID** и **Client secret**.
4. Откройте [developers.google.com/oauthplayground](https://developers.google.com/oauthplayground)
   → шестерёнка справа вверху → галочка **«Use your own OAuth credentials»** → вставьте Client ID
   и Client secret.
5. Слева внизу, в поле **«Input your own scopes»**, вставьте строку
   `https://www.googleapis.com/auth/youtube.upload https://www.googleapis.com/auth/youtube`
   → **Authorize APIs** → войдите в аккаунт, где канал (если спросят, выберите канал
   «Суть за минуту») → «Приложение не проверено» → **«Дополнительно» → «Перейти на страницу…»** →
   разрешите оба пункта.
6. **Step 2 → «Exchange authorization code for tokens»**. Скопируйте **Refresh token**.

**С компьютера**: `README.md`, раздел **«Загрузка на YouTube»** (`npm run youtube-auth`, тип клиента
«Desktop app»).

Потом добавьте все три ключа в GitHub: репозиторий → **Settings → Secrets and variables → Actions →
New repository secret**: `YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN`. Никому их не
отправляйте и не вставляйте в чат: с ними можно управлять каналом.

## Расписание: как ролики выходят сами

Время выхода задано в `channel.json`: **12:00 и 19:00 по Москве**, два ролика в день.
Переход на летнее и зимнее время учитывается, если поменять часовой пояс.

Как это устроено:

1. Программа загружает ролик **приватным** и сообщает YouTube время публикации (`publishAt`).
2. В **YouTube Studio → «Контент»** такой ролик помечен как **«Запланировано»** с датой и временем.
3. В назначенное время YouTube сам делает его **открытым**, подписчики получают уведомление.

До этого момента ролик можно открыть по ссылке из Studio, посмотреть и исправить название или
описание. Можно передвинуть время или отменить публикацию: в «Контенте» нажмите на
«Запланировано».

### Запуск с телефона или компьютера (GitHub)

**Actions → «video-studio: ролик» → Run workflow:**

| Что нужно | mode | script | upload | schedule |
|---|---|---|---|---|
| Один ролик в ближайший свободный слот | `render` | `video-studio/scripts/<файл>.json` | `youtube` | `slots` |
| Неделя роликов, каждый в свой слот | `batch` | `video-studio/scripts/sut-01*.json` | `release+youtube+instagram` (или `release+youtube`) | `slots` |
| Начать не сегодня, а с какой-то даты | как выше | как выше | как выше | `slots`, а в **schedule_start** — дату, например `2026-10-14` |

В режиме `batch` первый ролик встаёт в ближайший слот, второй в следующий, и так далее: 12:00,
19:00, на следующий день снова 12:00, 19:00. Маска `sut-01*.json` берёт все файлы, имя которых
начинается с `sut-01`, по алфавиту. Можно перечислить файлы и через запятую.

**Следующий пакет продолжит расписание сам.** Каждый ролик пакета сохраняется в релиз GitHub
вместе с файлом `youtube-result.json`, где записано время выхода. Новый пакет находит последний
запланированный ролик и ставит свой первый ролик в следующий слот. Для этого в `upload` должно
быть `release` или `instagram`. Одиночный `render` с `schedule = slots` тоже не займёт уже
занятый слот, если ролики хранятся в релизах. `schedule_start` нужен, только чтобы начать с
конкретной даты.

Сколько роликов в одном пакете:

- **8–10 штук.** Бесплатная квота голоса Gemini — примерно 10 роликов в сутки. Если она
  закончится, остальные ролики пакета озвучит другой голос (Edge).
- Загрузки через API YouTube не мешают: с декабря 2025 года бесплатной квоты хватает примерно на
  100 загрузок в сутки (раньше было около 6). Если у канала сработает свой суточный лимит загрузок,
  придёт понятная ошибка. Квота обновляется в полночь по тихоокеанскому времени, это 10:00 по Москве.
- Поэтому самый удобный ритм: **раз в 4–5 дней пакет из 8–10 роликов**, с `release` в `upload`.

### С компьютера

```bash
npm run make -- --script scripts/x.json --upload youtube --schedule            # ближайший свободный слот
npm run make -- --script scripts/x.json --upload youtube --schedule-slot 3     # третий слот от «сейчас»
npm run upload -- out/<папка> --schedule                                       # уже собранный ролик
npm run upload -- out/<папка> --publish-at 2026-10-10T12:00:00+03:00           # точное время
```

«Свободный» значит, что в этот слот ещё не поставлен другой ролик из папки `out/` на этом
компьютере. Что запланировано в GitHub, компьютер не видит. Для пакетов в GitHub используйте
`--schedule-slot` (это делает режим `batch`).

### Важно: проверка проекта Google

Если проект Google Cloud **не проходил проверку** (аудит API YouTube), YouTube **запирает все
загруженные через API ролики как приватные**, и расписание из программы не срабатывает. Тогда в
логе будет предупреждение «YouTube не подтвердил время публикации», а в Studio ролик не будет
отмечен как «Запланировано». Что делать:

- **Быстро, вручную.** YouTube Studio → «Контент» → нажмите на «Ограниченный доступ» у ролика →
  **«Запланировать»** → дата и время (они есть в сводке запуска GitHub и в `youtube-result.json`)
  → **«Запланировать»**. На один ролик уходит около 10 секунд.
- **Навсегда.** Подайте бесплатную заявку на аудит: форма «YouTube API Services — Audit and Quota
  Extension» в справке YouTube Data API. Проверка занимает от нескольких дней до нескольких недель.
  После неё ограничение снимается, и расписание работает само.

## Загрузили ролики руками — тексты и расписание поставит GitHub

Если загружаете видео сами, заполнять каждое не нужно.

1. Скачайте ролики со страницы «Ролики и оформление» (кнопка «Скачать видео»): имя файла
   начинается с кода ролика — `01a-…`, `01b-…`. Не переименовывайте их.
2. YouTube Studio → **«Создать» → «Добавить видео»** → выберите сразу все файлы (Studio берёт до
   15 за раз). Окно с названием и описанием можно просто закрыть: ролики останутся черновиками с
   «Ограниченным доступом».
3. Подождите 5–10 минут, пока YouTube их обработает. Затем в GitHub: **Actions →
   «video-studio: YouTube — тексты и расписание» → Run workflow** → **Run workflow**.

Что сделает запуск (данные — в `content/week1-videos.json`):

- найдёт каждый ролик по коду в имени файла или в названии-черновике (если имя потерялось — по
  длительности, когда она однозначна);
- поставит название, описание, теги, категорию «Образование», русский язык, «не для детей»,
  отметку «Изменённый контент: да»;
- назначит время выхода по слотам канала, два ролика в день, по порядку `01a`, `01b`, `02a`…
  Ролик, у которого время уже стоит, не сдвигается. С какого дня начать — поле **schedule_start**
  (например `2026-10-09`). Только тексты, без времени — **schedule = none**.

Внизу страницы запуска появится таблица: какой ролик нашёлся, ссылка на него в Studio и время
выхода. Запускать можно сколько угодно раз: заполненное пропускается. Сначала посмотреть без
изменений — галочка **dry_run**.

Если ролика нет в таблице: проверьте, что он загружен на этот канал, или впишите его код в начало
названия в Studio (например «01a») и запустите ещё раз. Если ролик загружен дважды, запуск его не
трогает: удалите лишний и запустите снова. Обложку у Shorts YouTube берёт кадром из видео — в
приложении YouTube её можно выбрать вручную.

С компьютера то же самое: `npm run youtube-fill` (параметры: `npm run youtube-fill -- --help`).
Так же устроена публикация в bakery-escape (`tools/studio/publish_plan.py`): файлы грузятся в Studio
руками, потому что YouTube запирает приватными ролики, загруженные через API непроверенным проектом
Google, а тексты и время ставятся через API — для таких роликов расписание работает.

Ролик, который YouTube ещё принимает (длительность пока 0), запуск не трогает и пишет «ещё
загружается» — запустите снова через 5–10 минут.

**Instagram так не умеет:** у API Instagram нельзя поменять подпись уже опубликованного Reels и
нельзя запланировать. Подпись вставляется вручную при публикации (кнопка «Копировать» на
странице), а запланировать можно в самом приложении: «Дополнительные настройки» →
«Запланировать».

## Если что-то не так

| Сообщение | Что делать |
|---|---|
| `время публикации … уже прошло` | Слот наступил раньше, чем закончилась сборка. Запустите с `schedule = slots` ещё раз: возьмётся следующий свободный слот |
| `YouTube отклонил время публикации` | То же самое: время в прошлом. Выберите слот позже |
| `invalid_grant` | Ключ YouTube устарел. Выполните `npm run youtube-auth` и обновите секрет `YT_REFRESH_TOKEN` |
| `исчерпана суточная квота` | На сегодня загрузки закончились. Повторите после 10:00 по Москве: `npm run upload -- out/<папка> --schedule` |
| Ролик не «Запланировано», а «Ограниченный доступ» | Проект Google не проверен, см. раздел выше |
| `у токена не хватает прав` | Ключ получен только с правом загрузки. Получите `YT_REFRESH_TOKEN` заново с двумя правами (шаг 6) и обновите секрет |
| В таблице «не найден» | Ролик не загружен на этот канал или YouTube его ещё не показывает. Подождите 5 минут, проверьте код в имени файла или названии, запустите снова |
