# Панель «Суть за минуту»

Веб-страница для телефона и компьютера, вход по паролю. Очередь из `content/plan.json` (60 тем),
этап каждого ролика — тема → сценарий → видео → в Studio → запланирован → вышел, напоминания,
перенос дня выхода, запуск сценариев, сборки и заполнения YouTube через GitHub Actions, автопилот.
На YouTube панель **не грузит** (загрузки через API от непроверенного проекта Google YouTube делает
приватными) — она напоминает и даёт скачать готовый файл.

## Экраны

- Оформление — в стиле канала (ночной фон, жёлтый акцент, шрифты бренд-кита). На компьютере —
  боковое меню и карточка ролика справа, на телефоне — нижние вкладки и карточка снизу.
- Переходы между вкладками мгновенные: сразу «скелет» экрана (`loading.tsx`), пока сервер собирает
  данные из GitHub и YouTube (базы у панели нет), а открытая за последнюю минуту вкладка при возврате
  показывается из памяти браузера (`staleTimes` в `next.config.ts`); «Обновить» — свежие данные.
- **Лента** (`/`) — кольцо запаса расписания, напоминания, дни по две крупные обложки (12:00 и 19:00)
  с этапом на обложке; фильтры по этапам. Даты запланированных — с YouTube, остальных — ориентир:
  следующие свободные слоты по очереди выхода. Обложка — с YouTube, у ещё не загруженных — из релиза
  (`/api/asset/<id>/file`, image/jpeg), без обложки в релизе — кадр из видео. «Выбрать» → отметить
  ролики → «⬇ Скачать»: видео и обложки пачкой (в напоминании «Ждут загрузки» — «Скачать все»).
- **Календарь** (`/?view=calendar`) — доска по неделям и единственное место, где меняется порядок
  выхода (экран «План» убран: он дублировал календарь; `/plan` ведёт сюда). Перетаскивание мышью или
  пальцем (нажать и подержать), без перетаскивания — нажать ролик, потом слот. Запланированный на YouTube переносится
  там же (занятый слот — обмен местами). Ориентиры (ещё не в расписании YouTube) меняются местами в
  очереди выхода — переменная `PANEL_QUEUE_ORDER`, в этом же порядке «Найти новые загрузки» раздаёт
  слоты. После переноса — «Отменить».
- **«Найти новые загрузки»** — одна кнопка: находит ролики, загруженные в Studio руками (код в имени
  файла), показывает, какое время им достанется, и после «OK» ставит название, описание, теги и
  время выхода. Уже заполненные ролики не трогает.
- **Карточка ролика** (снизу на телефоне, справа на компьютере): что делать дальше, видео и обложки
  одной кнопкой (iPhone — «📱 Сохранить в Фото» через меню «Поделиться», частями до 200 МБ; Android —
  скачивание; компьютер — файлами с кодом в имени: `08a-cover.jpg`), полоска идущей сборки, перенос (◀ день ▶ одним нажатием, занятый слот — обмен местами, «Отменить»), обложки и
  подпись для Reels, хук, угол и факты плана, текст сценария. У вышедшего — «💬 Первый комментарий»:
  черновик из вопроса призыва сценария и 1–2 источников плана → правка → «Опубликовать»
  (`commentThreads.insert`); если комментарий канала под роликом уже есть, второй не отправится.
  Закрепить — в приложении YouTube (API этого не умеет).
- **Запуски** (`/runs`) — «Сделать видео» / «Только сценарии» по темам плана; «YouTube: тексты
  и время» — подробная проверка: «Проверить» (ничего не меняет, показывает разницу построчно) →
  «Применить» для отмеченных, в том числе уже заполненных; автопилот; журнал запусков (у идущего —
  этап, доля и «осталось ≈ N мин» по медиане прошлых удачных запусков); ключи.
- **Статистика** (`/stats`) — цифры канала и роликов, монетизация, рубрики, хэштеги, расходы, а также:
  удержание из YouTube Analytics — «Досмотр» и «Средний просмотр» в обзоре и у каждого ролика,
  сортировка «Досмотр», «▼ слабый досмотр» (Shorts — меньше 50 %, длинные — меньше 30 %, от 20
  просмотров), порог монетизации — по засчитанным просмотрам. Нет права у ключа или API не включён —
  карточка «Удержание» с тем, что сделать (`../docs/youtube-setup.md`), остальная страница работает;
  «Слабый старт» — ролики 1–3 суток, у которых просмотров в сутки меньше половины медианы остальных
  Shorts за 30 дней (нужно хотя бы 5 для сравнения); «Придумать названия» запускает workflow
  «video-studio: названия» (`npm run title-ideas`, идеи — `content/title-ideas.json`), «Применить» после
  подтверждения меняет только название (`videos.update` части `snippet` с прежними описанием, тегами,
  категорией и языком), «Вернуть прежнее» — назад. «Лучшее время выхода» — медианы по слотам и дням
  недели у роликов старше 2 суток с уверенностью совета (`channel.json` не меняется). «Плейлисты
  рубрик» — «Проверить» (что создать и добавить, квота) → «Применить»: публичный плейлист на рубрику,
  в нём вышедшие и запланированные ролики, повтор не дублирует; связи и галочка «добавлять сами»
  (при «Найти новые загрузки») — переменная репозитория `PANEL_PLAYLISTS`.
- **TikTok** (`/tiktok`, ссылка вверху «Статистики») — подключение аккаунта (Login Kit, Sandbox) и его
  статистика: подписчики, лайки, ролики, просмотры за 30 дней, график, список роликов с кодами тем;
  как выкладывать (TikTok Studio, расписание до 10 дней) и пороги Creator Rewards. Установка —
  `../docs/tiktok-setup.md`. Ключи — `PANEL_TIKTOK` (AES-256-GCM от `TIKTOK_CLIENT_SECRET`).
- **Уведомления** (`/settings`, колокольчик вверху) — включить на этом устройстве, «Проверить»,
  «Выключить», список подписанных устройств.

## Установка на Vercel (один раз)

1. **PR с video-studio — в master.** Кнопки запуска работают только с workflow из ветки по умолчанию.
2. **Токен GitHub** — github.com/settings/personal-access-tokens/new → Fine-grained →
   Repository access: *Only select repositories* → `yt-planner` → Repository permissions:
   Actions — Read and write, Contents — Read and write, Variables — Read and write,
   Secrets — Read-only (панель видит только имена — каких ключей не хватает).
3. **Проект Vercel** — vercel.com → Add New → Project → Import `yt-planner` →
   Root Directory: `video-studio/panel` (Next.js определится сам; «Include files outside the root
   directory» оставьте включённым — панель берёт общий код из `video-studio/src`).
   Environment Variables — по `.env.example`: `PANEL_PASSWORD`, `SESSION_SECRET`, `GITHUB_TOKEN`,
   `GITHUB_REPO`, `GITHUB_BRANCH` (`master`), `YT_CLIENT_ID`, `YT_CLIENT_SECRET`,
   `YT_REFRESH_TOKEN` (как в `video-studio/.env`), `CRON_SECRET`. → Deploy.
4. Откройте ссылку и войдите паролем. На телефоне — «На экран „Домой“».
5. **Секреты GitHub Actions** (Settings → Secrets and variables → Actions): `GEMINI_API_KEY`
   (голос Charon — без него Actions озвучит Edge). Тексты и время на YouTube панель ставит сама,
   своими ключами из Vercel, — `YT_*` в GitHub нужны только для ручного запуска workflow
   youtube-fill. Панель напоминает, чего не хватает.
6. **Google**: OAuth-приложение — «In production», иначе `YT_REFRESH_TOKEN` перестаёт работать
   через 7 дней (docs/youtube-setup.md). В том же проекте Google Cloud включите **YouTube Analytics
   API** — без него в «Статистике» нет удержания.

Переменные Vercel меняются только с новым деплоем (Deployments → ⋯ → Redeploy).

## Уведомления на телефон

Утром — дела на сегодня (что загрузить в Studio, до какого дня хватит расписания), после сборки —
«видео готово». Web Push без сторонних сервисов и пакетов: подпись VAPID и шифрование — `lib/push.ts`
(`node:crypto`), устройства — переменная репозитория `PANEL_PUSH_SUBS` (до 10; отписавшиеся
убираются сами при следующей отправке). Без ключей панель работает как раньше, карточка
подсказывает, чего не хватает.

1. **Ключи** — в папке `video-studio`: `npx tsx panel/scripts/vapid-keys.ts ваша@почта.ru` → четыре
   строки (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `PANEL_NOTIFY_SECRET`) в Vercel →
   Environment Variables → Redeploy. Закрытый ключ — только в Vercel. Новая пара ключей отключает
   подписанные устройства: на каждом снова «Включить».
2. **iPhone** (iOS 16.4+): Safari → панель → «Поделиться» → «На экран „Домой“». Уведомления есть
   только у панели, открытой со значка: откройте её, войдите, колокольчик → «Включить» →
   «Разрешить» → «Проверить». Компьютер и Android — то же прямо в браузере.
3. **Из workflow** — `POST /api/notify`, заголовок `Authorization: Bearer <PANEL_NOTIFY_SECRET>`
   (подходит и `CRON_SECRET`), тело `{"title": "Видео готово", "body": "08a — загрузите в Studio", "url": "/"}`.
   Ответ — сколько устройств получили; ошибки уведомлений не роняют вызывающего.

## Как устроено

- Базы нет: план, сценарии, тексты для YouTube, релизы с видео и запуски — в GitHub, этапы и
  расписание — с YouTube. Ключи — только на сервере Vercel, в браузер не попадают.
- Поиск роликов на канале и слоты — общий код с `youtube-fill` (`src/pipeline/youtube-fill.ts`,
  `channel.ts`, `plan.ts`), поэтому панель и workflow всегда сходятся.
- Тексты и время на YouTube («Найти новые загрузки», «Применить») — `videos.update` прямо из
  панели, тем же кодом, что `youtube-fill` (`planUpdates` + `applyUpdate`): результат сразу.
- Квота YouTube (10 000 единиц в сутки): обновление очереди ≈ 3 единицы, «Проверить» ≈ 100
  (поиск свежих загрузок), «Найти новые загрузки» ≈ 200 + 50 на каждый заполненный ролик,
  перенос ≈ 51, обмен местами ≈ 102, смена названия ≈ 51; плейлисты: «Проверить» ≈ 15, создание
  плейлиста и добавление ролика — по 50 (не больше 40 вставок за одно «Применить»); первый
  комментарий: черновик ≈ 3, отправка ≈ 53. Удержание — один запрос к YouTube Analytics API на
  открытие «Статистики» (своя квота, Data API не тратит; ждём не дольше 10 с).
- Перенос — `videos.update` части `status` со всеми текущими полями; меняется только `publishAt`.
  Переносить можно только приватный ролик с будущим временем выхода.
- Автопилот — Vercel Cron раз в день (`vercel.json`, 03:00 UTC = 06:00 МСК; на бесплатном тарифе
  чаще нельзя). Ролики, которые выходят в ближайшие N дней и ещё без видео, — запуск
  «video-studio: ролик» (`batch`, `plan` = коды, в релиз): сценарий пишет Claude, ролик собирается.
  Не больше 6 за раз; без `GEMINI_API_KEY` в секретах не запускает (голос был бы не тот).
  Настройки и отметка о последнем запуске — переменные репозитория `PANEL_AUTOPILOT`,
  `PANEL_AUTOPILOT_LAST`.
- Instagram ждёт токен EAA; пока в карточке ролика — видео, обложка и подпись для ручного Reels.

## Разработка

```bash
cd video-studio/panel
npm install
npm run dev                          # http://localhost:3100, переменные — в .env.local
npm run build                        # сборка и проверка типов
cd .. && npx tsx panel/scripts/state-test.ts   # логика очереди без сети
npx tsx panel/scripts/push-test.ts              # уведомления: пример RFC 8291, VAPID, сводка — без сети
npx tsx panel/scripts/analytics-test.ts         # удержание и первый комментарий — без сети
```
